<h1>Language Krank</h1>

<p>
krank is a minimal production-rules engine whose notation a model can emit,
with a prose round-trip renderer that checks a translation against the original rules.
</p>

<h2>The round trip</h2>

<p>
A human writes intent in prose.
A model compiles the prose into a rule set: facts, and rules whose conditions and actions are JSON.
The engine evaluates the rule set deterministically and forward.
The renderer turns the rules back into prose, and a reader compares that prose with the original.
That comparison is the evidence that the compilation kept the meaning.
</p>

<p>
The aim is to shrink what the model must hold.
In a later iteration it receives the compiled rules and calls the engine to prove conformance,
instead of re-reading the full prose.
</p>

<p>
<a href="browser/index.html">The round-trip example</a> walks one translation:
the original prose, the compiled rules, the rules rendered back, the comparison, and the result.
<a href="browser/playground.html">The playground</a> edits a rule set and runs it.
</p>

<h2>The engine</h2>

<p>
A fact is a JSON object.
A rule has an <code>id</code>, a <code>when</code> conjunction, a <code>then</code> list of actions, and an optional numeric <code>priority</code>.
A condition matches by equality, by binding a value to a <code>$variable</code>, or by an operator object:
<code>eq</code>, <code>ne</code>, <code>lt</code>, <code>lte</code>, <code>gt</code>, <code>gte</code>, <code>in</code>.
A negated condition may reference a bound variable but may not bind a new one.
An action asserts, retracts, or emits; a rule binding fires once.
A <code>ruleset_session</code> keeps working memory and refraction across runs.
</p>

<p>
The library and renderer are browser-safe ES modules with no dependencies;
the command-line tool is Node-only.
The package is <code>@bannister.us/krank</code>.
</p>
